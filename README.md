# updoc

**updoc** = up-to-date docs —— 随代码保持最新的组件知识库。

Agent Skill：为代码组件建立和维护「知识库五件套」，把每次 AI 对话都要重做的代码交接，沉淀为持久的局部材料。

灵感来自 B 站 UP 主「原子能」的[知识衰减定律与组件知识库实践](https://www.bilibili.com/video/BV1gvpg6zEtT/)，经工程化整理而成。

## 为什么

- **知识衰减定律**：业务逻辑与决策考量散布在会议、邮件、PR 讨论里，必然随人员流动而流失。
- **每个新对话都是一次全新的代码交接**：AI 对没给的信息会自行脑补，理解误差到 review 才暴露。
- 代码写得再好，也无法说明它**为何而来、怎么来的**。

这个 skill 保存源码很难表达的四样东西：**设计意图、有效约束、失败经验、验收标准**。源码摘要不产生增量知识。

## 五件套

| 材料 | 回答的问题 | 防止的典型错误 |
|---|---|---|
| FLOW.md 流程图 | 这个组件实际怎样运行？ | 漏掉分支、误解状态与执行顺序 |
| DECISIONS.md 选型说明 | 为什么这样设计？哪些约束仍有效？ | 「顺手优化」破坏兼容性 |
| HISTORY.md 修改历史 | 它如何演变成现在这样？ | 重踩以前踩过的坑 |
| TODO.md 待办 | 哪些问题已知但未处理？ | 重复调查、擅自扩大任务 |
| SCENARIOS.md 测试案例 | 怎样判断行为没被破坏？ | 只看代码像对的就宣布完成 |

放在组件代码旁边的 `knowledge/` 目录里，而不是集中 docs/ ——知识作用域明确，agent 修改时一秒定位，省 token 也省探索。

## 安装

```bash
git clone https://github.com/tr1v3r/updoc ~/.config/dsh/skills/updoc
# 或任意你的 skills 目录，如 ~/.agents/skills/
```

## 使用

对 agent 说人话即可触发：

- 「给 internal/runner 建个知识库，AI 老是理解错它」
- 「我要让 agent 大改缓存组件，先帮我把交接材料准备好」
- 「改完代码了，把知识库同步一下」

Skill 覆盖全生命周期：

```
【bootstrap】划边界 → 读代码+挖 git → 采访维护者 → 生成五件 → 推测逐条求证
【维护】    改动类型 → 映射到该更新的件 → 只更新受影响的知识
```

## 结构

```
updoc/
├── SKILL.md                  # 主流程（先读这个）
└── references/
    ├── templates.md          # 五件套模板 + 好坏对比示例
    └── git-history.md        # git 挖掘命令 + 证据分级（A/B/C）
```
